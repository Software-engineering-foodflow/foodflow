# 貳、需求規格

## 一、功能需求分析

本節將系統功能需求依八大功能模組整理，以 Epic 與 User Story 描述各角色可執行的行為、預期取得的資訊及作業目的，作為後續功能清單、使用案例、流程設計與系統實作的依據。

系統使用者分為管理者與一般員工；以下所稱「員工」包含兩種角色，管理者專屬功能則另行標示。各功能依模組編號排列，並以 FR-01～FR-18 標示其需求對應關係。

### （一）Epic 1：帳號與權限管理模組

本 Epic 支援員工身分驗證、帳號維護與角色權限管理，使營運資料僅能由有效帳號依授權範圍存取，並保留歷史操作人員的識別資訊。

**User Story 1.1：登入與登出。**

As a 員工。

I want to 使用個人帳號與密碼登入系統，並於使用完畢後登出。

So that 我可以在通過身分驗證後執行工作，且登出後原登入狀態無法繼續操作。

**User Story 1.2：員工帳號管理。**

As a 管理者。

I want to 新增、修改及停用員工帳號，指派角色並重設密碼。

So that 我可以依人員職務與任職狀態管理系統使用資格，並保留既有交易中的歷史操作者資訊。

**User Story 1.3：角色權限控管。**

As a 管理者。

I want to 系統依管理者與一般員工的角色，在伺服器端驗證每項操作權限。

So that 員工僅能執行獲授權的功能，直接存取未授權功能時亦會被拒絕。

對應需求：FR-01、FR-02。帳號不得重複；最後一名有效管理者不得被停用或降權，停用帳號的既有登入亦須失效。

### （二）Epic 2：基本資料與儲存位置管理模組

本 Epic 集中維護食材、分類、供應商及儲存位置，提供進貨、庫存查詢、領用與預警作業所需的共用資料，並維持歷史交易的資料關聯。

**User Story 2.1：食材與分類管理。**

As a 管理者。

I want to 新增、修改及停用食材與分類，設定食材的庫存單位、保存方式及安全庫存量。

So that 員工可以使用一致的食材資料登記交易，系統亦能依安全庫存量判斷缺料風險。

**User Story 2.2：供應商管理。**

As a 管理者。

I want to 維護供應商名稱、聯絡人、聯絡方式與啟用狀態。

So that 員工可以選擇有效供應商建立進貨單，並追查歷史進貨來源。

**User Story 2.3：儲存位置管理。**

As a 管理者。

I want to 維護儲存位置代碼、名稱、儲存類型及說明。

So that 員工可以在進貨時指定有效位置，並於查詢與領用時找到食材。

**User Story 2.4：整批儲存位置變更。**

As a 管理者。

I want to 登記批次的整批位置變更及原因，保留原位置、新位置與操作時間。

So that 批次位置可以反映實際存放情形，且後續能追查移位歷程。

對應需求：FR-03～FR-05。已被交易引用的資料須保留歷史關聯；停用食材不得新增進貨，但既有庫存仍可領用、報廢與查詢。一個批次僅登記一個位置，不提供部分數量移位。

### （三）Epic 3：進貨與批次管理模組

本 Epic 將實際收貨資料轉為可追溯來源與效期的批次庫存，區分草稿與已確認進貨，並提供歷史查詢及符合條件的沖銷作業。

**User Story 3.1：建立及編輯進貨草稿。**

As a 員工。

I want to 選擇供應商與進貨日期，登記各筆食材的數量、單價、到期日及儲存位置，並儲存為草稿，於確認前修改內容或刪除草稿。

So that 我可以先整理收貨資料，於確認前核對內容，且草稿不影響庫存。

**User Story 3.2：確認入庫與建立批次。**

As a 員工。

I want to 確認進貨單後，由系統為每筆明細建立唯一批次及進貨異動。

So that 食材可以正式計入庫存，並保留各批次的來源、到期日、位置及進貨單價。

**User Story 3.3：進貨紀錄查詢。**

As a 員工。

I want to 依日期、供應商、食材及單號查詢進貨紀錄，並由批次追查來源單據與明細。

So that 我可以核對收貨內容及確認食材的進貨來源。

**User Story 3.4：進貨沖銷。**

As a 管理者。

I want to 對尚無後續庫存異動的已確認進貨填寫原因並整單沖銷，再重新建立正確單據。

So that 錯誤入庫可以在保留原始紀錄的情況下更正，且不破壞後續交易關聯。

對應需求：FR-06、FR-07。同一食材若到期日或位置不同，須分開明細；確認入庫時到期日必填，整張單全部成功或全部不生效，重複確認不得重複入庫。已有後續庫存異動時不得直接沖銷。

### （四）Epic 4：批次庫存查詢模組

本 Epic 提供食材總覽、批次明細與來源追查，協助員工同時掌握數量、位置及效期，並區分可使用與已過期的庫存。

**User Story 4.1：庫存總覽查詢。**

As a 員工。

I want to 依食材名稱、分類、保存方式、位置及狀態搜尋庫存，分別查看實體庫存量、可用庫存量、過期量與安全庫存量。

So that 我可以掌握實際存量與可供領用的數量，作為備料及補貨的依據。

**User Story 4.2：批次明細與異動追查。**

As a 員工。

I want to 展開食材的各個批次，查看批號、來源、進貨日期、到期日、位置、初始量、剩餘量與狀態，並連結至來源進貨及相關異動。

So that 我可以辨識各批次的差異，並追查庫存變化的原因。

對應需求：FR-08、FR-09。位置篩選後的數量僅合計該位置批次，低庫存仍依全店可用量判定；不同食材、不同單位不得合併為單一數量，已耗盡批次仍須保留歷史紀錄。

### （五）Epic 5：食材領用與消耗登記模組

本 Epic 支援員工依實際備料需求領用食材，以 FEFO 原則提供批次建議，並記錄實際領用批次與數量，使庫存變化可追溯。

**User Story 5.1：FEFO 領用建議。**

As a 員工。

I want to 選擇食材與需求量後，查看系統依到期日先後提供的批次、位置與建議領用量。

So that 我可以優先使用較早到期的食材，並在單一批次不足時依建議跨批次領用。

**User Story 5.2：非 FEFO 批次選擇。**

As a 員工。

I want to 在實際作業需要時改選其他可用批次，並填寫偏離 FEFO 建議的原因。

So that 我可以記錄實際拿取情形，且系統能保留非 FEFO 領用標記供後續追查。

**User Story 5.3：確認領用與扣除庫存。**

As a 員工。

I want to 核對一個以上批次的實際領用數量後，確認扣除庫存並建立各批次的領用異動。

So that 帳面庫存可以反映實際消耗，並保留操作者、時間與批次紀錄。

**User Story 5.4：領用紀錄與沖銷。**

As a 員工。

I want to 查看最近的領用紀錄，並在登記錯誤時填寫原因，沖銷整次領用。

So that 我可以將原領用量加回對應批次，保留原紀錄及沖銷依據，再重新登記正確領用。

對應需求：FR-10、FR-11。到期日相同時依進貨日期、批號排序；過期與零庫存批次不得領用，領用量不得超過提交當下剩餘量。多批次領用全部成功或全部不生效，多人同時操作亦不得產生超領。

### （六）Epic 6：效期與低庫存預警模組

本 Epic 於站內集中呈現需要處理的批次及食材，協助員工安排優先領用、報廢與補貨，並由管理者維護全店預警天數。

**User Story 6.1：效期提醒查詢。**

As a 員工。

I want to 查看過期、今日到期及即期批次的食材、批號、位置、數量、單位、到期日與剩餘天數。

So that 我可以辨識應優先使用或確認報廢的批次，避免將過期食材用於備料。

**User Story 6.2：低庫存提醒。**

As a 員工。

I want to 在啟用食材的全店可用庫存量小於或等於安全庫存量，且安全庫存量大於零時，查看食材名稱、可用量、安全庫存量與缺口量。

So that 我可以掌握缺料風險，及早安排補貨。

**User Story 6.3：預警首頁與作業連結。**

As a 員工。

I want to 登入後在首頁依過期、今日到期、即期、低庫存的順序查看預警，依狀態與位置篩選，並進入對應的領用、報廢或建立進貨單功能。

So that 我可以從需要處理的項目直接開始作業，並在重新整理或操作成功後取得最新資訊與更新時間。

**User Story 6.4：預警天數設定。**

As a 管理者。

I want to 設定全店適用的預警天數，並於後續查詢套用新規則。

So that 我可以依餐廳作業需要調整即期食材的提醒範圍。

對應需求：FR-12～FR-14。效期以 Asia/Taipei 當日日期計算，過期、今日到期與即期互斥；零庫存批次不列入待處理預警。停用食材或安全庫存量為 0 時不產生低庫存提醒，過期量不計入可用量。預警天數僅接受非負整數，設為 0 時不產生即期提醒；過期批次不得透過預警連結領用。

### （七）Epic 7：報廢與盤點模組

本 Epic 支援食材損耗登記及帳實差異調整，透過原因、操作者與異動紀錄保存庫存變更依據，並計算可確認的報廢損失金額。

**User Story 7.1：報廢登記。**

As a 員工。

I want to 選擇批次並登記報廢數量與原因，由系統扣除庫存，同時建立報廢紀錄及庫存異動。

So that 無法使用的食材可以正確移出庫存，並保留損耗原因與責任追溯資訊。

**User Story 7.2：過期批次全數報廢。**

As a 員工。

I want to 從過期預警選擇批次，確認後將其剩餘量全數報廢，原因預設為「過期」。

So that 我可以快速完成已確認過期食材的報廢登記，並使歸零批次移出待處理預警。

**User Story 7.3：盤點差異調整。**

As a 管理者。

I want to 輸入批次實際盤點量與原因，核對帳面量及差額後確認調整。

So that 庫存可以反映實際清點結果，並保留調整前後數量及原因。

對應需求：FR-15、FR-16。報廢量須大於零且不得超過剩餘量；損失金額為報廢量乘以批次進貨單價，無單價時記為未知，不視為零。盤點實際量不得小於零，無差額時不新增數量異動；預覽後庫存若被他人變更，須拒絕舊確認並要求重新核對。

### （八）Epic 8：異動紀錄與統計模組

本 Epic 提供庫存變化追查、期間收支核對及報廢分析，協助員工了解食材流向，並由管理者檢視損耗分布與已知損失金額。

**User Story 8.1：庫存異動查詢。**

As a 員工。

I want to 依日期、食材、批次、異動類型與操作者查詢庫存異動，查看來源單據、增減量、前後量、原因及是否為非 FEFO 領用。

So that 我可以追查各筆數量變化，並核對交易及批次紀錄。

**User Story 8.2：期間庫存統計。**

As a 員工。

I want to 依日期區間查看各食材的期初量、進貨量、領用量、報廢量、調整量與期末量。

So that 我可以核對期間庫存收支，確認期初量加計各項淨異動後與期末量一致。

**User Story 8.3：報廢分布與損失金額分析。**

As a 管理者。

I want to 設定日期區間，並選擇依食材、分類或原因分組查看報廢數量及損失金額，並展開明細核對。

So that 我可以辨識主要損耗來源，作為調整採購、保存與領用作業的參考。

對應需求：FR-17、FR-18。已確認的庫存異動紀錄不可直接修改或刪除，位置變更與數量異動分開呈現；沖銷須連結原紀錄並於實際確認當日反映。統計須符合「期初量＋淨進貨量－淨領用量－淨報廢量＋調整淨額＝期末量」，不同單位分別呈現；損失金額僅加總有單價的紀錄，並標示未知成本事件數。統計以日期區間為範圍，不套用異動清單的食材、批次、類型與操作者篩選。報廢分布與損失金額僅供管理者檢視。

## 三、功能清單說明

### （一）1.0 模組：帳號與權限管理模組

帳號與權限管理模組負責系統登入驗證、員工帳號維護及操作授權，讓各項營運作業均可識別操作者，並依角色限制可存取的功能。帳號停用後仍保留歷史交易中的操作者資訊，避免影響資料追溯。

- 1.1 登入與登出：員工以有效帳號與密碼登入，驗證失敗時顯示不區分帳號或密碼錯誤的訊息；登出後原登入狀態失效，未登入者不得取得營運資料。

- 1.2 員工帳號管理：管理者可新增、修改及停用帳號、指派角色與重設密碼，帳號不得重複。停用帳號不得登入，其既有登入的後續請求亦須遭拒；最後一名有效管理者不得被停用或降權。

- 1.3 角色權限控管：系統依管理者與一般員工的權限範圍，於伺服器端驗證操作資格。一般員工即使直接存取管理功能，仍不得執行未授權操作或取得受限資料。

### （二）2.0 模組：基本資料與儲存位置管理模組

基本資料與儲存位置管理模組提供各項交易共用的食材、分類、供應商及位置資料。管理者負責維護，一般員工僅能查詢；已被引用的資料須保留歷史關聯，並以啟用或停用狀態控制後續使用。

- 2.1 食材與分類管理：管理者可新增、修改及停用食材與分類，維護食材名稱、分類、庫存單位、保存方式及安全庫存量。已有庫存或歷史交易的食材不得刪除或直接更換單位；停用食材不得新增進貨，但既有庫存仍可領用、報廢及查詢，有啟用食材的分類不得停用。

- 2.2 供應商管理：管理者可維護供應商名稱、聯絡人、電話、其他聯絡資訊及狀態，名稱必填且至少提供一種聯絡方式。已有進貨紀錄的供應商不得直接刪除，停用後不得用於新進貨，但歷史單據仍可查詢。

- 2.3 儲存位置管理：管理者可維護唯一的位置代碼、名稱、儲存類型及說明，供進貨與批次作業選用。進貨時只能選擇有效位置，有剩餘庫存的位置不得停用。

- 2.4 整批儲存位置變更：管理者可登記批次整批換位置的原因，系統保留原位置、新位置、操作者及時間。每個批次僅登記一個位置，移位不改變數量與到期日，不提供部分數量移位。

### （三）3.0 模組：進貨與批次管理模組

進貨與批次管理模組將收貨資料轉為正式批次庫存，透過草稿、確認與沖銷區分單據狀態，並保存供應商、進貨明細與批次間的來源關聯。已確認進貨不得直接覆寫或刪除，須依規定處理錯誤紀錄。

- 3.1 建立及編輯進貨草稿：員工可選擇供應商與進貨日期，填寫一筆以上食材明細，記錄數量、單價、到期日與儲存位置。同一食材若到期日或位置不同須分開明細；草稿不增加庫存，草稿可暫缺數量、到期日與位置，確認前須補齊；草稿可修改或刪除，已確認單據不可直接編輯。

- 3.2 確認入庫與建立批次：員工確認單據後，系統驗證數量、日期及相關資料，為每筆明細建立唯一批次及進貨異動，並保存可選填的進貨單價。整張單全部成功或全部不生效，重複確認不得重複入庫。

- 3.3 進貨紀錄查詢：員工可依日期、供應商、食材及單號查詢進貨紀錄，查看單據與明細。各批次亦可追查原進貨單、明細及供應商，供收貨核對與來源追溯。

- 3.4 進貨沖銷：管理者可對尚無後續庫存異動的已確認進貨填寫原因並整單沖銷，再重建正確單據。已有後續庫存異動的批次不得直接沖銷，本系統以盤點調整處理數量差異，原始紀錄仍須保留。

### （四）4.0 模組：批次庫存查詢模組

批次庫存查詢模組提供食材層級的庫存總覽及批次層級的詳細資訊，協助員工同時掌握數量、效期、位置與來源。系統將實體庫存量與可用庫存量分開呈現，避免將尚未報廢的過期量當成可供領用的庫存。

- 4.1 庫存總覽查詢：員工可依食材名稱、分類、保存方式、位置及正常、即期、今日到期、過期、低庫存等狀態篩選，查看實體庫存量、可用庫存量、過期量及安全庫存量。位置篩選後僅合計該位置批次並標示條件，低庫存仍依全店可用量與安全庫存量判定；不同食材或單位不得合併為單一數量。

- 4.2 批次明細與異動追查：員工可展開各食材的批次，查看批號、來源、進貨日期、到期日、位置、初始量、剩餘量及狀態，依到期日排序並連結來源進貨及相關異動。已耗盡批次仍保留歷史紀錄，但不計入可用量與待處理預警。

### （五）5.0 模組：食材領用與消耗登記模組

食材領用與消耗登記模組依員工實際拿取的批次與數量記錄消耗，並以 FEFO 原則提供領用建議。系統須在確認當下檢查可用量，確保多人操作或跨批次領用時仍維持正確庫存。

- 5.1 FEFO 領用建議：員工選擇食材與數量後，系統列出未過期且有剩餘量的批次，依到期日、進貨日期及批號排序，顯示位置與建議領用量。最早到期批次不足時接續建議下一批，需求超過可用量時拒絕並顯示目前可用量。

- 5.2 非 FEFO 批次選擇：員工可依實際拿取情形調整領用批次與數量。系統依本次總領用量重新計算各批次的 FEFO 建議分配量；當某批次的實際領用量超過其建議分配量時，員工須為該批次填寫原因，系統並將該批次的領用異動標記為「非 FEFO」。過期及零庫存批次不得選用。

- 5.3 確認領用與扣除庫存：員工核對一筆以上批次與實際領用量後確認，系統扣除庫存並為各批次建立領用異動。領用量須大於零且不得超過提交當下剩餘量；「顆」「個」等不可分割的計數單位，領用量僅接受整數，其他單位最多三位小數。多批次操作全部成功或全部不生效；同時領用造成庫存不足時，失敗者須收到最新可用量與提示。

- 5.4 領用紀錄與沖銷：員工可查看最近 20 次領用紀錄及各批次明細，填寫原因後沖銷整次領用。系統將原領用量加回各批次，新增連結原異動的沖銷紀錄；原領用紀錄保留，重複沖銷不重複增加庫存。

### （六）6.0 模組：效期與低庫存預警模組

效期與低庫存預警模組依當日日期、到期日、預警天數與安全庫存量，呈現需要處理的批次及食材。本系統以站內預警支援領用、報廢及補貨判斷，預警資訊於頁面載入、重新整理及操作成功後更新。

- 6.1 效期提醒查詢：系統以 Asia/Taipei 當日日期區分過期、今日到期與即期批次，顯示食材、批號、位置、數量、單位、到期日及剩餘天數，各效期狀態不重複計數。已用完或全數報廢批次不列入待處理預警，過期批次須由員工登記報廢，不自動扣除庫存。

- 6.2 低庫存提醒：當食材為啟用狀態、安全庫存量大於零，且全店可用庫存量小於或等於安全庫存量時，系統於首頁與庫存總覽顯示食材名稱、可用庫存量、安全庫存量與缺口量。過期量不計入可用量，補貨後高於安全庫存量即解除提醒，安全庫存量為零或食材已停用時不提醒。位置篩選不改變全店低庫存判定，畫面另列該位置的可用量；缺口量為安全庫存量減全店可用量，最低為零。

- 6.3 預警首頁與作業連結：員工登入後可依過期、今日到期、即期、低庫存的順序查看預警，依狀態與位置篩選，並進入對應的領用、報廢或建立進貨單功能。畫面須顯示更新時間，過期批次不得透過連結進行領用。

- 6.4 預警天數設定：管理者可設定全店預警天數，僅接受非負整數，更新後的新查詢套用新規則。設定為零時不產生即期提醒，過期與今日到期狀態仍依日期規則判定。

### （七）7.0 模組：報廢與盤點模組

報廢與盤點模組記錄無法使用的食材及實際盤點差異，以報廢紀錄或調整異動修正庫存，保留原因與操作者資訊。損失金額依批次進貨單價計算，相關報廢分布與金額資訊依管理者權限提供。

- 7.1 報廢登記：員工可選擇批次、輸入報廢量，並登記過期、變質、損壞或其他原因，選擇其他時須補充說明。確認後同步扣除庫存、建立報廢紀錄與異動；報廢量須大於零且不得超過剩餘量，損失金額為報廢量乘以批次進貨單價，無單價時記為未知。

- 7.2 過期批次全數報廢：員工可從過期預警一鍵選擇批次剩餘量全數報廢，原因預設為「過期」，經確認後生效。全數報廢後剩餘量歸零並移出待處理預警，相關歷史紀錄仍可查詢。

- 7.3 盤點差異調整：管理者輸入批次實際盤點量與原因，系統顯示帳面量與差額，確認後建立可追查前後數量的調整異動。實際量不得小於零，無差額時不新增數量異動；預覽後若庫存被他人變更，須拒絕舊確認並要求重新核對。

### （八）8.0 模組：異動紀錄與統計模組

異動紀錄與統計模組提供庫存歷程追查及期間收支核對，讓員工了解食材進出與庫存變動原因。管理者另可查看報廢分布及損失金額，作為檢視損耗來源與調整作業方式的依據。

- 8.1 庫存異動查詢：員工可依日期、食材、批次、類型及操作者查詢異動，查看時間、來源單據、增減量、前後量、原因及非 FEFO 標記。紀錄不可修改或刪除，沖銷須可追查原紀錄，位置變更與數量異動分開呈現。

- 8.2 期間庫存統計：員工可依日期區間查看各食材的期初量、進貨量、領用量、報廢量、調整量與期末量，並以各項淨異動核對期末庫存。統計依確認時間計算，沖銷於實際確認當日歸入對應項目且不得重複計數，不同單位分別呈現。

- 8.3 報廢分布與損失金額分析：管理者可設定日期區間，並選擇依食材、分類或原因分組查看報廢數量與損失金額，並展開明細核對。統計僅套用日期區間；金額僅加總有進貨單價的事件，另標示未知成本事件數，一般員工不得存取報廢分布與損失金額。
