# 壹、系統整體概述

本文件旨在界定「食序 FoodFlow：餐飲食材庫存與效期預警系統」於餐廳日常營運中的定位、使用者類型與系統邊界，說明系統所提供的服務、各類使用者的操作範圍，以及系統與外部作業之間的分界，作為後續功能需求、流程設計與資料規格之共同依據。

## 一、系統定位

「食序 FoodFlow」為支援單一門市、非連鎖獨立餐廳之食材庫存與效期管理系統，以門市內部的日常庫存作業為使用情境。使用者可透過平板或電腦的網頁介面，完成進貨登記、批次庫存查詢、食材領用、效期與低庫存預警、報廢登記及盤點調整等作業。

本系統以「庫存批次」作為食材追蹤的核心，分別記錄各批次的進貨來源、到期日、儲存位置、進貨單價與剩餘數量，並區分實體庫存量與可用庫存量。領用時，系統依先到期先使用（First Expired, First Out，FEFO）原則提供批次建議，協助員工確認應優先使用的食材；同時呈現過期、今日到期、即期與低庫存提醒，供人員安排領用、補貨或報廢。

系統集中保存進貨與庫存異動紀錄，並提供庫存及報廢統計，使餐廳能追查食材來源、數量變化與損耗原因。效期提醒依人員輸入的日期與預警設定產生，食材實際狀況仍須由餐廳人員確認。

## 二、使用者類型

本系統依使用者的操作權限，區分為兩種類型：

1. 管理者：主要由餐廳負責人或店長擔任，負責員工帳號與權限管理、食材與分類維護、供應商與儲存位置管理，以及預警設定。管理者亦可執行進貨、領用、領用沖銷、報廢與庫存查詢等日常作業，並具有盤點調整、進貨沖銷及檢視報廢分布與損失金額的權限。

2. 一般員工：主要包含收貨、採購及廚房備料人員，依實際工作需要執行進貨登記、庫存與批次查詢、食材領用、領用沖銷、報廢登記及預警查詢，並可查看庫存異動與期初期末統計。一般員工可查詢基本資料，但不具有帳號管理、基本資料維護、預警設定、盤點調整及進貨沖銷等管理權限。

收貨、採購與廚房備料屬於餐廳內部的工作分工，均依管理者或一般員工身分使用系統。供應商僅作為進貨來源與聯絡資料的管理對象，不登入本系統。

## 三、系統邊界

本節界定系統內部負責的功能與外部作業範圍，以明確區分系統紀錄、資訊提示及人員實際作業之間的責任。

### （一）系統內部邊界

系統內部負責之範圍包含：

1. 帳號與權限管理：提供員工登入、登出、帳號新增、修改、停用及密碼重設功能，並於伺服器端驗證各項操作權限。

2. 基本資料與儲存位置管理：維護食材、食材分類、供應商及儲存位置，記錄食材單位、保存方式與安全庫存量，並保留整批位置變更歷程。

3. 進貨與批次管理：建立進貨草稿，於確認入庫後依各筆明細建立庫存批次與進貨異動，保存來源、數量、單價、到期日及位置，並提供符合條件之進貨整單沖銷。

4. 批次庫存查詢：提供食材總覽與批次明細，分別呈現實體庫存量、可用庫存量、過期量及安全庫存量，並可追查來源進貨與相關異動。

5. 食材領用與消耗登記：依 FEFO 原則建議領用批次，經員工確認實際批次與數量後扣除庫存。員工可調整實際領用批次與數量；系統依本次總領用量重新計算 FEFO 建議分配，當某批次的實際領用量超過其建議分配量時，須填寫原因，系統並將該批次的領用異動標記為「非 FEFO」。過期及零庫存批次不得領用。領用登記錯誤時，可填寫原因沖銷整次領用，再重新登記。

6. 效期與低庫存預警：依當日日期、批次到期日、預警天數及安全庫存量，於站內呈現過期、今日到期、即期及低庫存提醒，並提供前往相關作業的入口。

7. 報廢與盤點管理：登記報廢批次、數量、原因及損失金額，並由管理者依實際盤點結果確認調整差額。過期批次不自動扣除庫存，須經人員確認後登記報廢。

8. 異動紀錄與統計：保存進貨、領用、報廢、盤點調整及沖銷紀錄，記錄操作者、時間、來源與數量變化，提供庫存收支統計及依權限開放的報廢分析。

### （二）系統外部邊界

本系統不處理且不負責的範圍包含：

1. 多門市與跨店作業：不提供連鎖總部管理、跨分店庫存整合、跨店調撥或中央廚房生產排程。

2. 銷售與食譜扣料：不提供菜品、食譜及銷售登錄自動扣料，也不串接真實 POS 系統；食材消耗由員工依實際領用情況登記。

3. 採購與會計流程：低庫存提醒僅提供補貨判斷所需資訊，不自動建立採購訂單、不向供應商下單，也不處理付款、應付帳款或其他會計作業。

4. 外部通知服務：僅提供站內預警，不包含 Email、簡訊、LINE 或背景推播通知。

5. 硬體辨識與環境監控：不提供條碼辨識、OCR、感測器監控或原生行動應用程式，亦不自動取得食材重量、到期日或儲存環境資訊。

6. 實體作業與食材安全判定：食材收貨、搬移、領用、清點及實體報廢由餐廳人員執行。系統不自行推算未標示、開封或解凍後的保存期限，也不以日期提醒取代人員對食材是否可用的判斷。
